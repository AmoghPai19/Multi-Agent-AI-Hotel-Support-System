# HotelSupportState & Intent Enum Contract

## Purpose

This document freezes the `HotelSupportState` schema and the `Intent` enum used by FastAPI, LangGraph, Conversation Agent, Reservation Agent, and Compliance Agent.

The field names, types, optionality, and enum values defined here are the source of truth for integration.

Renaming or changing these fields requires a contract version update.

---

# Source of Truth

This contract is the canonical definition of `HotelSupportState`.

The implementation in `graph.py` must conform to this contract.

---

# HotelSupportState (Frozen)

| Field | Type | Required | Description |
|--------|------|----------|-------------|
| user_message | str | Yes | Original user request received by FastAPI. |
| guest_id | str | Yes | Unique guest identifier. |
| intent | Intent | No | Detected conversation intent. Set by Conversation Agent. |
| draft_response | str | No | Draft response generated by the Conversation Agent. |
| reservation_data | ReservationData | No | Output returned by the Reservation Agent. |
| compliance_status | ComplianceStatus | No | Final compliance verdict returned by the Compliance Agent. |

---

# Intent Enum (Frozen)

| Value | Meaning |
|--------|---------|
| GREETING | Greeting or welcome message. |
| RESERVATION | Reservation-related request. |
| GENERAL_QUESTION | General hotel information or FAQ. |

# State Lifecycle

The following sequence describes how `HotelSupportState` flows through the system during request processing.

```text
FastAPI
    │
    ▼
Initialize HotelSupportState
(user_message, guest_id)
    │
    ▼
Conversation Agent
    │
    ├── Updates:
    │      intent
    │      draft_response
    │
    ▼
Reservation Agent (Only when intent == RESERVATION)
    │
    └── Updates:
           reservation_data
    │
    ▼
Compliance Agent
    │
    └── Updates:
           compliance_status
    │
    ▼
FastAPI / WebSocket
    │
    └── Reads:
           draft_response
           reservation_data
           compliance_status
    │
    ▼
Final Response Returned to Guest
```

### Lifecycle Rules

- FastAPI initializes the `HotelSupportState`.
- The Conversation Agent is the only component that updates `intent` and `draft_response`.
- The Reservation Agent executes only for `RESERVATION` intents and updates only `reservation_data`.
- The Compliance Agent performs the final validation and updates only `compliance_status`.
- FastAPI / WebSocket reads the final state and returns the appropriate response to the guest.
- Every component must respect the ownership rules defined in this contract.

---

# Integration Rules

- Field names are frozen and must not be renamed.
- Field types and optionality are frozen.
- Intent enum values are frozen.
- Agents may update only their owned fields.
- All inter-agent communication occurs through `HotelSupportState`.
- Any schema change requires a new contract version.
