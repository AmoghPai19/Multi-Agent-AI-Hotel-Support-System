# Reservation Dispatch Contract

## Purpose

This document defines the communication contract between the Conversation Agent and the Reservation Agent. It specifies how reservation requests are identified, what information is passed, and what the Reservation Agent returns. This contract is frozen for the current implementation.

---

# Workflow

```text
FastAPI
    ↓
LangGraph
    ↓
Conversation Agent
    ↓
Reservation Agent
    ↓
Compliance Agent
    ↓
FastAPI Response
```

---

# Dispatch Rule

The Reservation Agent is executed **only when:**

```text
intent == RESERVATION
```

For all other intents, LangGraph routes directly to the Compliance Agent.

---

# Conversation Agent Output

When a reservation request is detected, the Conversation Agent returns:

| Field | Type | Description |
|------|------|-------------|
| intent | Intent | RESERVATION |
| draft_response | str | Initial draft response generated by the Conversation Agent |
| tool_name | ReservationTool | Reservation operation to execute |
| tool_arguments | dict | Typed arguments required for the selected reservation tool |

---

# Supported Reservation Tools

The Conversation Agent may request exactly one of the following tools:

- `create_reservation`
- `modify_reservation`
- `cancel_reservation`
- `check_availability`
- `get_reservation_details`

Only **one reservation tool** is selected for each reservation request.

---

# Typed Tool Argument Contracts (Frozen)

The **Conversation Agent** is responsible for:

- Detecting the reservation intent
- Selecting the correct reservation tool
- Extracting the required information from the user's request
- Building the typed `tool_arguments` payload

The Conversation Agent **does not perform business validation or execute reservation operations**.

The **Reservation Agent** is responsible for validating business rules (availability, booking rules, reservation existence, hotel policies, etc.) before executing the selected reservation operation.

# Reservation Agent Input

The Reservation Agent receives:

- guest_id
- user_message
- intent
- draft_response
- tool_name
- tool_arguments

The Reservation Agent validates the business rules and executes the selected reservation tool using the supplied typed arguments.

---

# Reservation Agent Output

The Reservation Agent updates **only**:

```python
reservation_data
```

The output is the complete **ToolResult envelope**.

```python
reservation_data = {
    "status": "...",
    "booking_id": "...",
    "data": {
        ...
    },
    "message": "..."
}
```

### Status Values

The Reservation Agent may return one of the following status values:

- SUCCESS
- FAILED
- NOT_FOUND
- VALIDATION_ERROR
- SYSTEM_ERROR

### Meaning

| Field | Description |
|------|-------------|
| status | Reservation execution status |
| booking_id | Reservation identifier (if available) |
| data | Tool-specific response payload |
| message | Human-readable result returned by the reservation tool |

The Reservation Agent **must not modify**:

- intent
- draft_response
- compliance_status

---

# Ownership

## Conversation Agent

Responsible for:

- Detect reservation intent
- Select reservation tool
- Extract user information
- Build typed `tool_arguments`

The Conversation Agent **never executes reservation operations directly**.

---

## Reservation Agent

Responsible for:

- Validate business rules
- Execute the selected reservation tool
- Return `reservation_data`

The Reservation Agent does **not** determine intent or modify conversation state.

---

## LangGraph

Responsible for:

- Route execution
- Pass `HotelSupportState` between agents

LangGraph performs orchestration only.

---

## Compliance Agent

Responsible for:

- Validate the final response
- Apply business and compliance rules
- Produce the final response returned to FastAPI

---

# Rules

- Only reservation requests invoke the Reservation Agent.
- One reservation request maps to exactly one reservation tool.
- All communication happens through `HotelSupportState`.
- The Conversation Agent never performs reservation operations directly.
- The Conversation Agent provides the typed `tool_arguments` payload.
- The Reservation Agent performs business validation before execution.
- The Reservation Agent updates **only** `reservation_data`.
- `reservation_data` represents the complete `ToolResult` envelope, **not only** the `data` field.

# Design Summary

This contract freezes the complete interface between the Conversation Agent and the Reservation Agent.

It defines:

- The Conversation Agent output (`tool_name` + typed `tool_arguments`)
- The input schema for all five reservation tools
- The Reservation Agent input
- The Reservation Agent output (`ToolResult` envelope)
- Status values returned by the Reservation Agent
- Ownership and responsibilities of every component
- Communication rules through `HotelSupportState`

This document serves as the single source of truth for Reservation Agent integration.
